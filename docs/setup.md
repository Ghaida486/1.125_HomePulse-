# HomePulse — installation and reproduction

See the [project README](../README.md) for the implemented features, technology and results.
The commands below run from the repository root.

## Open the prepared web app

```bash
python3 -m http.server 8767 --directory web-app-20261116/dist
```

Open `http://127.0.0.1:8767/`. The included aggregate snapshot needs no ML installation
and covers September–November 2026.

## Rebuild the monthly data and models


Use **Python 3.12**. The November 14 check uses a new virtual environment, the pinned
packages and freshly downloaded, checksum-verified EIA files. The current package
includes the studied state workbook and cleaned CSV. The RECS CSV is downloaded
separately; SQLite databases and model binaries are generated by the following build.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m pip install -e . --no-deps
python -m pip check
python scripts/download_monthly_sources.py
python experiments/state-forecast-20261113/run_experiment.py
python experiments/state-forecast-20261113/verify_and_report.py --checks-only
python scripts/build_monthly.py --source-project . --output-project .
pytest -q tests/test_peer_matching.py tests/test_monthly.py tests/test_monthly_map.py
streamlit run app.py --server.address 127.0.0.1
```

The experiment fits six prespecified candidates, chooses settings using validation
errors, freezes that choice, and evaluates the later test period. The verification
script independently checks saved-model predictions, metrics, source values and
future-data leakage. The build then creates the app's forecast snapshot. These
commands reproduce an existing study; they do not provide a new untouched test set.

The experiment refuses to overwrite an existing evaluated test. The monthly builder
also refuses to replace an existing database. Repeat the build in a clean copy.
No model files or database from the original project are needed for this sequence.
The source installer uses the included state workbook after verifying its checksum.
The external downloads are Python packages and the RECS CSV, unless a verified
local copy of that CSV is supplied.

**Source versions matter.** The included workbook preserves the state release used
for the reported results. The source installer checks fixed SHA-256 values and stops
if a file differs; it never substitutes a revised release silently. To reuse other
verified local sources instead of downloading:

```bash
python scripts/download_monthly_sources.py --cache-project /path/to/previous/HomePulse
```

A changed workbook requires a separately versioned study and refreshed evaluation.
The [data guide](../data/README.md) describes the included state files and source links.
The large RECS CSV remains a checksum-verified download.

The core build uses Plotly in the app and does not require matplotlib. To regenerate
optional static experiment charts, install matplotlib and run
`python experiments/state-forecast-20261113/verify_and_report.py` without `--checks-only`.
Static chart files are not required for app operation. On macOS, XGBoost may require
an installed OpenMP runtime (`libomp`); the tested Apple Silicon machine already has it.


## Original annual workspace


Earlier implementation modules are retained for traceability and to support the
prototype workspace switch. They are not the current monthly setup.
The annual workspace needs its own databases and models; without them it shows a
preparation message. Its trained artifacts are not required by the monthly app.

The complete local regression suite covers both workspaces; `pytest -q` therefore
requires the older annual fixtures too. `pytest -q tests/test_peer_matching.py tests/test_monthly.py tests/test_monthly_map.py` is the current
monthly acceptance suite and is run during the clean monthly rebuild.


## Portable verification

```bash
python3 scripts/check_submission.py
node web-app-20261116/scripts/verify.mjs
node web-app-20261116/scripts/verify-contracts.mjs
```

The first checks the selected repository files and report consistency; the second
checks browser calculations against the saved Python reference cases. These checks
do not measure individual household predictive accuracy. Python monthly tests need
the generated database, while the portable snapshot checks do not.

## Refresh aggregate browser evidence

After the database exists, regenerate the public aggregate summaries and reference
scenarios using the current Python matcher, then run both Node checks above:

```bash
python web-app-20261116/scripts/export_snapshot.py --project .
```

Use `--database /path/to/homepulse_monthly.sqlite` to read an existing snapshot
without copying it into this checkout. Individual household records are not exported.
